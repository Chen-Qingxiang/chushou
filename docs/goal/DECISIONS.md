# 关键决策索引

## ADR-0001：采用静态优先的 npm workspace

状态：接受
日期：2026-07-13

### 决策

采用 React + TypeScript + Vite，并按 `apps/web`、`packages/schema`、`packages/domain`、`tools/ingest` 分层。权威数据保存在 Git 中，构建时严格校验并生成前端分片、索引和导出。

### 理由

公共阅读无需服务器；研究数据可以 review、diff、release 和长期维护；同一 schema 可约束编辑源、领域查询、UI 和导出。当前四文件 MVP 已无法承载版本化来源、跨文件关系和测试。

### 不选择

- 不继续扩大单一 `data.js`。
- 不让公共站点依赖本地 PostgreSQL 或私人 API。
- 不在第一阶段引入图数据库；图是事实层的可重建投影。

## ADR-0002：除授使用独立领域模型并与 SongScope 对齐

状态：接受
日期：2026-07-13

### 决策

吸收 SongScope 的实体／事件／状态／断言／证据分层，但使用独立 `chs:` 稳定 ID 和针对官制的更细语义。外部对齐通过 `ExternalIdentifier`，不共享数据库主键。

### 理由

除授需要表达时期化官名、三层语义投影、品秩体系、官衔顺序、任命动作和处分限制；这些是清晰而独立的领域边界。独立 ID 避免两个仓库发布节奏耦合。

## ADR-0003：三层轨道是受控投影，不是互斥本体分类

- 状态：接受
- 日期：2026-07-13

### 决策

底层 `TitleUsageVersion` 可关联一个或多个语义角色，并记录争议；UI 将它投影为身份与等级、荣誉与资历、实际工作三条核心轨道，必要时另显示地点与处分。

### 理由

同一名称可能随时期改变性质，也可能兼有实际职责与身份标签。强迫每项头衔永远进入一个桶会制造错误；完全不分类又无法帮助初学者理解。

## ADR-0004：正式数据采用证据门禁而非“看起来完整”

- 状态：接受
- 日期：2026-07-13

### 决策

面向用户的 accepted/reviewed 实质断言必须至少有支持证据。没有来源的旧 MVP 内容不迁移；未知内容以 gap、unresolved span 或 research queue 明示。生产校验拒绝 placeholder 标记。

### 理由

研究可信度高于记录数量。显式缺口可以被继续校订，伪完整会污染搜索、比较和导出。

## ADR-0005：路径工具先回放证据，不提前生成概率树

状态：接受
日期：2026-07-13

### 决策

任官路径实验室第一阶段只回放 release 中已经通过门禁的真实任命序列，并对到任、处分、未解析成分和时间精度运行可解释检查。官衔构造实验只组合当前时期可用的 `TitleUsageVersion`，不写回数据。进士入仕、磨勘、荐举、丁忧、回避、台谏、贬谪和量移等通用转移规则，在适用期、支持证据、反例和概率方法进入 schema 前不开放选择。

### 理由

目前只有苏轼 13 条 partial 任命与三名反例人物各一条小切片，不足以训练或人工指定可外推的晋升概率。真实序列回放已经能帮助用户区分授命、任事和政治状态，同时避免把一个人的经历伪装成制度必然。

## ADR-0006：多维轨迹先发布分类信号，不用缺证数据拟合折线

状态：接受
日期：2026-07-13

### 决策

政治位置页分别显示中央核心程度、实际权力、名义品级、资望和皇帝信任相关五条轨。`packages/domain` 只从已发布 appointment、title usage、institution、rank、service 和 action type 生成三类结果：史料／结构事实、可复算规则信号、coverage gap。每格公开方法、说明和 assertion；不生成总分，也不把缺失当零。

### 理由

当前数据只有一条独立 `CareerMetricAssessment`，不足以支持跨生涯连续数值。分类轨仍能让用户比较同一次变化在各维度的不同含义，同时保持可解释、可测试和不伪精确。恢复／召还、责降／安置只被标为制度动作代理，明确不是对皇帝心理的事实判断。

## ADR-0007：解码与派生规则必须只有一个领域实现

状态：接受
日期：2026-07-13

### 决策

UI 只负责呈现 `packages/domain` 的解码与职业信号结果。最长匹配、时期候选、动作词、时间副词、动作组、未知 span 和职业分类规则不得在 React 页面复制一套；测试直接调用同一领域函数。

### 理由

浏览器展示、单测和未来批处理若各自维护词典与规则，会产生无法审计的多套“事实”。单一领域实现保证站点、测试和后续导出能够用相同输入重放相同结果。
