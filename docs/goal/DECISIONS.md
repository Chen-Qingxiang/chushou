# 关键决策索引

## ADR-0001：采用静态优先的 npm workspace

状态：接受  
日期：2026-07-13

### 决策

采用 React + TypeScript + Vite，并按 `apps/web`、`packages/schema`、`packages/domain`、`tools/ingest` 分层。权威数据保存在 Git 中，构建时严格校验并生成前端分片、索引和导出。

### 理由

公共阅读无需服务器；研究数据可以 review、diff、release 和长期维护；同一 schema 可约束编辑源、领域查询、UI 和导出。当前四文件 MVP 已无法承载版本化来源、跨文件关系和测试。

### 不选择

- 不继续扩大单一 `data.js`。
- 不让公共站点依赖本地 PostgreSQL 或私人 API。
- 不在第一阶段引入图数据库；图是事实层的可重建投影。

## ADR-0002：除授使用独立领域模型并与 SongScope 对齐

状态：接受  
日期：2026-07-13

### 决策

吸收 SongScope 的实体／事件／状态／断言／证据分层，但使用独立 `chs:` 稳定 ID 和针对官制的更细语义。外部对齐通过 `ExternalIdentifier`，不共享数据库主键。

### 理由

除授需要表达时期化官名、三层语义投影、品秩体系、官衔顺序、任命动作和处分限制；这些是清晰而独立的领域边界。独立 ID 避免两个仓库发布节奏耦合。

## ADR-0003：三层轨道是受控投影，不是互斥本体分类

状态：接受  
日期：2026-07-13

### 决策

底层 `TitleUsageVersion` 可关联一个或多个语义角色，并记录争议；UI 将它投影为身份与等级、荣誉与资历、实际工作三条核心轨道，必要时另显示地点与处分。

### 理由

同一名称可能随时期改变性质，也可能兼有实际职责与身份标签。强迫每项头衔永远进入一个桶会制造错误；完全不分类又无法帮助初学者理解。

## ADR-0004：正式数据采用证据门禁而非“看起来完整”

状态：接受  
日期：2026-07-13

### 决策

面向用户的 accepted/reviewed 实质断言必须至少有支持证据。没有来源的旧 MVP 内容不迁移；未知内容以 gap、unresolved span 或 research queue 明示。生产校验拒绝 placeholder 标记。

### 理由

研究可信度高于记录数量。显式缺口可以被继续校订，伪完整会污染搜索、比较和导出。
