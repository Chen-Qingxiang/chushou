## 可复现门禁

```bash
npm ci
npm run ci
npm run test:e2e
```

`npm run ci` 校验格式、lint、严格类型、curated 数据、提交的 JSON Schema、14 条单元／集成测试、生产构建和静态性能预算。Playwright 运行 19 条 Chromium 测试，其中包含解码、时期切换、证据、复制深链接和移动导航等命名流程，以及 13 个代表性页面的 axe WCAG A／AA 扫描、console error 检查和键盘焦点旅程。GitHub Pages workflow 只上传并发布通过这些门禁的同一份 `dist/`。

独立的 `npm run quality:lighthouse` 在移动模拟下测量首页、官名详情、苏轼官履、制度地图和多维轨迹：Performance 90／98／98／98／98，Accessibility 均为 100，LCP 2.11–2.24 秒，CLS 为 0–0.009。首测未达标的路由只重测一次，连续失败仍使命令失败；最终五条路由均一次通过。原始基线保存在 `docs/reports/lighthouse-baseline.json`。

## 明确边界

- 59 个官名概念／60 个时期版本是北宋中央核心切片，不是全宋官名全集；
- 3 个品秩方案和 13 个阶位条目只表达已经核对的局部顺序；
- 人物任命顺序不被解释成因果、概率或通用晋升树；
- 自动 axe 与 Lighthouse 不等于完整真实辅助技术审计；
- 研究预览应回查可靠点校本，并同时引用 assertion／passage ID 与底层来源定位。

后续扩展应优先取得合法年谱核对条件、补卷 338 gap、扩大品秩方案及反例人物覆盖，而不削弱现有 evidence gate。
