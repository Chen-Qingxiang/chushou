# 「除授」总目标执行计划

更新日期：2026-07-13  
状态：研究预览版已交付；持续扩充中

## North Star

系统必须能以可核查的证据回答：某人在某一时点拥有的一串官衔分别表示什么制度身份、资望与实际工作；它们在当时处于什么机构、品秩和政治语境中；一次除授是否形成实际任职；此后各维度为什么变化。

所有 schema、数据、生成物和界面都必须服务这个问题。记录数量不能替代证据质量。

## 不可妥协的发布规则

1. 生产数据中的实质历史断言必须关联至少一条证据；无证据候选只能进入研究队列或测试 fixture。
2. 史料原文、来源定位、标准化事实、研究解释、规则投影和界面白话必须分层。
3. 任命动作与实际任职阶段分离；一次任命的有序官衔成分不得被压成单一 title。
4. 官名、机构、品秩、地名和关系均带有效期；时期浏览镜头不是事实有效期。
5. 冲突断言并存，支持、反对、限定和派生关系可检查；后写入记录不得静默覆盖旧记录。
6. 权威编辑源位于 `data/curated/`，`data/generated/` 只能由确定性构建产生。
7. 正式站点和 release 导出不得混入 `demo`、`placeholder`、`待补` 等伪装成史实的内容。

## 阶段与 release gate

### 阶段 0：事实、技术与产品审计

交付：

- 当前仓库、历史、工作区、部署和全部源码审计；
- MVP 内容保留／迁移／隔离／删除清单；
- 本地 SongScope 设计书与 schema 差异分析；
- 研究来源、许可、引用和录入规范；
- 重大决策记录。

完成条件：所有现有生产数据都被标记为可迁移候选、待证据重录或应隔离，不默认继承为史实。

### 阶段 1：正式 schema 与数据流水线

交付：

- npm workspace：`apps/web`、`packages/schema`、`packages/domain`、`tools/ingest`；
- Zod 类型、JSON Schema 导出、受控词表和跨文件校验；
- 人工审阅 JSON 数据、确定性生成器、搜索索引和 JSON/CSV 导出；
- coverage 与 data-quality 报告；
- schema、引用、日期、版本和证据测试。

完成条件：无来源 accepted 断言、断裂引用、无效日期、非法词表、重叠版本或 placeholder 会使校验失败。

### 阶段 2：正式应用迁移

交付：

- React + TypeScript + Vite 静态应用替换根目录 MVP；
- GitHub Pages base path、真实路由、刷新可恢复的深链接；
- 保留纸色、朱砂、墨色、宋体和克制的书卷视觉；
- 统一页面外壳、设计 token、移动导航、加载／错误／空状态、打印引用视图；
- 所有界面只消费生成数据投影。

完成条件：旧 `data.js` 不再是生产事实源；新应用可构建、可部署、可键盘操作。

### 阶段 3：第一条成品级纵向切片

交付：

- 神宗—哲宗为核心的北宋文官制度骨架；
- 50–100 个经过来源检查的核心官名／制度概念；
- 以选定权威年谱为覆盖锚点的苏轼官履 coverage matrix；
- 全部官衔成分解析或明确记录 unresolved span；
- 王安石、司马光、章惇各至少一条真实反例切片；
- 来源、证据、争议和导出浏览。

完成条件：coverage report 明确分母、已覆盖、缺口和缺口原因；不再以代表节点声称完整。

### 阶段 4：核心产品体验

依次完成并以深链接验收：

1. 引导首页；
2. 全局搜索与时期化官名详情；
3. 时间化、有方向和类型的制度地图；
4. 两时点制度沿革比较；
5. 苏轼三轨官履与除授详情；
6. 多维政治位置曲线及依据；
7. 可解释原文解码器；
8. 官职、人物和任命比较；
9. 来源与证据浏览器；
10. 学习路径；
11. 有证据和规则说明的任官路径模拟器；
12. 筛选结果和 release 数据导出。

### 阶段 5：质量、发布与维护

交付：

- format、lint、strict typecheck、schema validation、unit、integration、E2E、build；
- GitHub Actions 与 Pages；
- WCAG 2.2 AA 检查、桌面／移动浏览器 QA、性能预算和 Lighthouse 记录；
- README、设计书、数据字典、贡献指南、许可、引用方式和最终交付报告。

完成条件：完整 CI 等价命令通过，关键用户流程无控制台错误、断链或明显溢出。

## 增量工作原则

- 每个里程碑结束时保持可构建、可校验；
- 普通可逆决策自主完成并写入 ADR；
- 无法取得关键材料时将具体缺口写入研究队列，继续不依赖该材料的工作；
- 只在确需授权、受版权材料或外部账号动作时向用户阻塞；
- 每次发布报告同时面向初学者、研究者和维护者检查完整链路。
