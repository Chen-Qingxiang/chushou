# 引用与证据规范

## 必须区分的四层

1. `Source`：抽象作品，例如《宋史》；
2. `Edition`：具体文本或出版形态，例如某数字转录或点校本；
3. `SourceLocator`：卷、门类、页、条目、段落、URL fragment 等结构化定位；
4. `Passage`：在该定位下保存的必要短原文、转录与校订状态。

不得只写“见《宋史》”。不知道页码时保留为空，不得编造；可用真实卷次、条目或稳定数字锚点定位。

## 断言与证据

- `EvidenceLink.relation` 使用 `supports`、`contradicts`、`qualifies`、`mentions`、`derives_from`、`corrects`。
- `basis` 区分明文、上下文推断、编年推断、异文、学术解释、外部对齐和算法候选。
- accepted/reviewed 的实质断言至少需要一条 `supports`。
- 白话说明引用其所解释的 assertion，不直接把 passage 文本改写成无来源新事实。
- 多条材料若共享同一来源，要记录来源依赖，不能按独立证据重复计数。

## 引用显示

面向用户的引用至少显示：

```text
作品；作者／编者；版本或数字文本；卷／门类／页／条目；短原文；状态；稳定链接；访问日期
```

界面必须能够从结论进入 assertion，再进入 passage 与 locator；冲突和限定证据并列显示。

## 转录

- 保存原文字符，不以自动简繁转换覆盖；
- 另存 Unicode 规范化和简繁检索字段；
- 自动标点、OCR 或转录需记录工具、版本和人工复核状态；
- 现代标点不能伪装成古籍原版标点。
